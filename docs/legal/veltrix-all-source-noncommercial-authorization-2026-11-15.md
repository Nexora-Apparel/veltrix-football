# VELTRIX FOOTBALL 2.0 — Project-wide source authorization policy

**Recorded:** 2026-11-15  
**Status:** USER-CONFIRMED AUTHORIZATION — NON-COMMERCIAL ONLY  
**Scope:** All source providers, datasets and data streams that the project owner has obtained authorization to use for VELTRIX FOOTBALL 2.0, including the OpenPlay / WhoScored / Opta historical dataset.

## Project-owner authorization

The project owner has explicitly confirmed:

> "we can use it as we see fit as long as we don't monitise it that the condition I got from all our sources"

The project therefore records that the source permissions obtained by the project owner authorize VELTRIX FOOTBALL to use the covered source data for project work without commercial exploitation.

## Permitted VELTRIX project uses

Subject to each source's technical access, safety and data-integrity controls, the confirmed non-commercial scope includes:
- collection and automated acquisition;
- caching, storage, archival retention and historical import;
- parsing, normalization, deduplication and cross-source reconciliation;
- internal analysis, research and feature engineering;
- model training, validation, benchmarking and backtesting;
- creation and internal/public display of derived football analysis and predictions for non-commercial project use;
- combining authorized source observations into VELTRIX-owned derived datasets and models.

## Non-commercial condition

- No monetisation of source data, data-derived services or VELTRIX outputs.
- No paid subscriptions, paid data access, advertising-funded data exploitation, resale, sublicensing or commercial licensing.
- Do not enable commercial use flags in source-approval records.
- Any future monetisation proposal requires fresh written authorization and a new rights review before any commercial activity.

## Source-level controls remain mandatory

This policy resolves the project's rights hold for sources the project owner confirms are covered. It does not invent API entitlements, bypass authentication, rate limits, paid-plan requirements, provider quotas, or technical access blocks. It also does not make source data point-in-time: every record must preserve its true source timestamps, VELTRIX retrieval/recording timestamps, exact source revision and content hash.

Maintain source-specific attribution, provenance, retention and security conditions. Raw-source redistribution is not enabled by this policy; only derived non-commercial project outputs are enabled unless a source-specific record expressly permits raw redistribution.

## Operational decision

- Rights-based quarantine for covered project sources: **LIFTED**.
- Non-commercial collection, storage, analysis, feature research, training and validation: **AUTHORIZED**.
- Monetisation/commercial use: **PROHIBITED**.
- Technical and point-in-time qualification: **STILL REQUIRED**.
- Production publication, value-betting certification and scheduling: **UNCHANGED**.

This record reflects the project owner's authorization statement and must be used as the non-commercial rights overlay when registering source approvals. Do not represent an inaccessible endpoint or an unverified timestamp as qualified merely because rights are resolved.
